Idle-timeout middleware (HIPAA-3, §164.312(a)(2)(iii) Automatic Logoff).

For cookie-session-protected routes: enforce that the session is dropped when the user has been idle longer than IdleTimeoutMiddleware::seconds. Configurable via SESSION_IDLE_TIMEOUT_SECS; defaults to 900s (15min) per HHS OCR guidance for systems handling PHI.

§Behavior

On each request:

  1. If the session has no post-cutover SessionUser, pass through unchanged.
  2. If last_active_at is missing (first authenticated hit), stamp now and continue.
  3. If now - last_active_at > idle_timeout, purge the session and redirect to /signin?reason=idle. The user must re-authenticate.
  4. Otherwise, refresh last_active_at = now and continue.

Idle timeout is enforced independently of the absolute session lifetime configured in [actix_session]. A long-lived session that goes idle still gets logged out. A short-lived session that’s actively used still expires on its absolute deadline.

Stateless API requests (JWT-bearer, no session) are unaffected: they have no session, so step 1 short-circuits.
